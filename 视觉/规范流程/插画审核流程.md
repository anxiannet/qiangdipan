# 《夕妖：抢地盘》插画审核规范流程

## 文件定位

本文件用于维护基础版插画生成、审核与迭代流程。

本文件只维护通用规范与流程，不维护单卡具体视觉设计。

单卡具体视觉设计来源：

```text
妖怪志/卡名/卡名.md
法宝志/法宝名/法宝名.md
```

规则、数量、星级、卡面文案、技能评分、审核状态唯一来源：

```text
规则/V1.2-基础卡表.md
```

视觉安全区、卡框、UI 规范来源：

```text
视觉/规范/视觉总规范.md
视觉/规范/UI规范.md
```

---

## 一、通用视觉原则

| 项目 | 要求 |
|---|---|
| 主体识别 | 玩家 1 秒内看出主角是谁，不靠读技能理解 |
| 技能匹配 | 动作、表情、道具、场景必须服务当前已审核技能 |
| 独立轮廓 | 同组角色必须有不同剪影、姿态和主道具 |
| UI 安全 | 脸、手、核心道具、技能动作不得被星数、名称栏、技能栏遮挡 |
| 风味表达 | 台词、动作、场景可增加代入感，但不得改写规则 |
| 禁止重复 | 不能让两张不同卡看起来像同一张卡换色 |

## 二、读取流程

生成或审核单张图前，必须按顺序读取：

1. `当前项目记忆.md`
2. `规则/V1.2-基础卡表.md`
3. 对应 `妖怪志/卡名/卡名.md` 或 `法宝志/法宝名/法宝名.md`
4. `视觉/规范/视觉总规范.md`
5. `视觉/规范/UI规范.md`
6. 本文件：`视觉/规范流程/插画审核流程.md`

若单卡志与基础卡表冲突，以基础卡表中的卡名、数量、星级、卡面文案、评分、审核状态为准。

若视觉文件与规则文件冲突，以规则文件为准；视觉只能表现规则，不能新增规则或解释规则。

## 三、单卡图生成流程

1. 确认该卡是否属于当前基础版。
2. 确认该卡技能是否已审核。
3. 读取单卡志中的视觉形象设计、视觉差异要求与视觉安全区要求。
4. 生成图片前先确认主体、动作、表情、道具、场景、禁止撞点。
5. 生成后逐项审核。
6. 不合格则重做，保留迭代记录，不覆盖旧图。
7. 合格后再进入卡面合成或成品卡面环节。

---

## 四、基础版角色独立性检查表

每张图生成或审核时，必须逐项检查：

| 检查项 | 合格标准 |
|---|---|
| 角色名称遮住后是否仍能区分 | 能通过轮廓、动作、道具识别大致角色 |
| 技能文案遮住后是否仍能猜到技能方向 | 能从动作和场景看出查牌、喊名、吹回、消灭、抓走等方向 |
| 同组角色是否撞动作 | 不允许同组角色都只是站立、挥手、奔跑或放风 |
| 同组角色是否撞道具 | 关键道具不能共用为主视觉，例如算盘 / 名册 / 三张牌要区分 |
| 同组角色是否撞场景 | 场景可同体系，但必须有不同功能空间：账房、点将台、洞口、战场等 |
| 是否误导规则 | 不能画出卡面没有的效果，例如消灭3星、跨地盘、回血、额外抽牌 |
| 是否符合安全区 | 脸、手、核心道具、技能特效不得被 UI 栏遮挡 |

## 五、单图审核输出模板

每张图审核必须输出：

```text
卡名：
技能一致性：合格 / 不合格
主体轮廓：合格 / 不合格
动作表情：合格 / 不合格
道具场景：合格 / 不合格
同组差异：合格 / 不合格
UI安全区：合格 / 不合格
是否需要重做：是 / 否
问题说明：
```

## 六、迭代与归档要求

- 之前生成的旧图不得覆盖。
- 试玩版旧图按试玩版目录归档。
- 新基础版图片按基础版目录保存。
- 每张图一张一张生成，一张一张审核。
- 不合格图片可以保留为迭代记录，但不得作为最终基础版图。
- 每张卡的迭代记录放入该卡对应文件夹。

推荐路径：

```text
妖怪志/卡名/插画/
法宝志/法宝名/插画/
```

---

## 七、维护原则

1. 本文件只维护通用流程与审核规范。
2. 单卡具体视觉设计只写入对应妖怪志或法宝志。
3. 不在 `视觉/插画设计/` 下维护第二份单卡视觉设计文档。
4. 若技能调整，先同步基础卡表和单卡志，再更新视觉设计。
5. 视觉内容不得修改规则、数量、技能、胜利条件或卡表。
