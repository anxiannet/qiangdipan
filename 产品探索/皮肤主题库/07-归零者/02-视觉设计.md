---

## 二、视觉情绪

不是传统赛博朋克的霓虹混乱，而是“冷静、干净、残酷的系统秩序”。

高层区域：白、银、蓝，秩序、洁净、权限充足。  
底层区域：黑、灰、红色拒绝提示，临时线路、废弃服务器、手工改装装备。

核心对比：

```text
系统很干净
人被排除在外
越权装备有粗粝生命力
Root Access 的光是冷白与青蓝
卡牌本体必须有收藏卡的厚重质感
```

当前修正方向：

```text
不要大面积纯白留白
不要过度刮痕和脏纹理
不要轻飘UI说明卡
需要深色金属框、净面材质、半透明深色技能区、清晰文字
```

## 三、角色方向

- 零权限黑客：破解节点。
- 蜂鸟无人机手：侦察权限链路。
- 机修师：用机修装甲强行重启硬件锁。
- 装甲执行者：正面接管节点。
- 身份伪造师：恢复或封锁身份权限。
- 医疗权限师：抢占医疗舱调用权。

角色不能只是职业名，需要有代号、关系和阶层反差。

示例代号：

```text
蜂鸟 Hummingbird
扳手 Wrench
白鸦 White Raven
断电者 Blackout
红钥 Red Key
门徒 Gateborn
铁翼 Iron Wing
根号零 Root Zero
```

## 四、卡牌框架方向

### 执行者卡

```text
尺寸：63 × 88 mm 竖版
主体：人物占画面70%以上
左上：权限等级 / 星级
右上：不放归零者品牌图标
底部：名称、职业标签、文字技能区
品牌：仅在右下角保留一个“归零者 / ZERO ACCESS”角标
```

视觉重点：

```text
人物被系统拒绝，但正在越权接入。
背景可以出现 Access Denied、临时线路、破损终端、权限光环。
```

### 越权模块卡

```text
尺寸：63 × 88 mm 竖版
主体：装备占画面60%以上
背景：系统HUD、警报框、数据流
左侧或左上：越权模块 / OVERRIDE MODULE、功能分类
底部：文字技能区
品牌：仅在右下角保留一个“归零者 / ZERO ACCESS”角标
```

视觉重点：

```text
装备不是普通武器，而是强行越权的工具。
模块卡必须和角色卡、权限节点卡一眼区分。
```

### 权限节点卡

```text
尺寸：88 × 63 mm 横版
主体：城市系统设施 / 服务器 / 设备节点
无角色技能区
强调所属系统域颜色与节点功能
品牌：仅保留一个“归零者 / ZERO ACCESS”角标
```

视觉重点：

```text
节点必须像可被接管的城市基础设施。
不能画成普通战场据点。
```

## 五、技能区与语言版式

当前决策：不再使用图标语言作为卡面技能表达核心。

原因：

```text
如果图标不能完全替代文字，就会同时占用图标区与文字区。
这会降低卡面收藏感，也会让实体卡更像教学说明卡。
```

正式卡面改为：

```text
中文主版：技能区留够 1 行中文规则。
英文版：使用同一套边框，技能区留够 2 行英文规则。
```

中英文版本必须使用同样边框结构：

```text
同一套卡框
同一套插画区
同一套标题区
同一套技能区尺寸
同一套品牌角标
只替换语言文本
```

技能区原则：

```text
1. 不做大图标解释链。
2. 不在技能区堆多个说明图标。
3. 可保留极少量类型装饰图标，但不承担规则解释。
4. 规则文字必须独立可读。
5. 中文规则尽量压缩为1行。
6. 英文规则允许2行。
```

示例：

```text
中文版：使用：保护你的1个权限节点，持续1回合。
英文版：Use: Protect 1 of your Access Nodes for 1 round.
```

## 六、颜色逻辑

| 状态 | 颜色方向 | 用途 |
|---|---|---|
| 零权限 | 红色 / 暗红 / 黑灰 | Access Denied、被拒绝、系统警报 |
| 越权中 | 橙黄 / 警告黄 | Override、破解过程、风险状态 |
| 已授权 | 青蓝 / 冷白 | Access Granted、节点接管 |
| Root Access | 白金 / 青蓝高亮 | 胜利、最高权限、系统接管 |

---

## 七、符号系统方向

图标不再作为技能语言使用，但仍可以作为视觉符号系统使用。

允许保留的符号用途：

| 符号概念 | 中文 | 英文 | 用途 |
|---|---|---|---|
| 门 | 门禁 | Access | 门禁域节点识别 |
| 十字 / 医疗舱 | 医疗 | Medical | 医疗域节点识别 |
| 小型飞行器 | 无人机 | Drone | 无人机域节点识别 |
| 钱包 / 芯片 | 信用 | Credit | 信用域节点识别 |
| 人像锁 | 身份 | Identity | 扩展候选 |
| 井号 / 根符号 | 根权限 | Root | 胜利 / 顶级权限视觉 |
| 盾形离线框 | 离线保护 | Offline Shield | 防御型模块分类 |
| 禁止符号 | 取消 | Cancel | 系统拒绝 / 取消类氛围 |

注意：

```text
符号用于识别类型、系统域、状态和氛围。
符号不再负责完整解释技能规则。
```

## 八、系统域视觉区分

| 系统域 | 视觉元素 | 建议主色 |
|---|---|---|
| 门禁域 | 门、闸机、电梯、封锁线 | 冷白 + 蓝 |
| 医疗域 | 医疗舱、纳米液、生命曲线 | 白 + 青绿 |
| 无人机域 | 蜂鸟无人机、空域网格、机群 | 深蓝 + 青蓝 |
| 信用域 | 芯片钱包、账本、债务库、铸机 | 黑金 + 紫 |

## 九、禁止方向

```text
不要做普通赛博朋克霓虹街头
不要做现实黑客键盘敲代码感
不要做普通雇佣兵枪战
不要做现实政治或现实国家符号
不要让角色只像战术士兵，必须体现权限夺取主题
不要大面积纯白留白
不要过度刮痕、污渍和脏旧纹理
不要把卡面做成教学说明页
不要让图标链抢占技能区
```
