# 《夕妖：抢地盘》单卡卡志页面结构设计

## 文件定位

本文件只设计单卡卡志页面的展示结构。

本文件暂不填充具体卡牌内容、原著背景、形象描述、技能设计解释或规则数值。

本文件不新增卡牌，不修改规则，不维护第二份卡表。

卡牌基础数据唯一来源：

```text
规则/V1.2-基础卡表.md
```

单卡扩展说明来源：

```text
妖怪志/卡名/卡名.md
法宝志/法宝名/法宝名.md
```

如单卡志文档不存在，页面只显示基础卡牌信息和占位状态，不临时编写背景。

---

## 一、页面定位

单卡卡志页用于展示一张卡牌背后的完整设计档案。

它不是第二份卡表，也不是规则来源。

它负责展示：

```text
1. 卡牌基础信息
2. 原著背景来源
3. 角色形象方向
4. 卡面美术要点
5. 技能设计灵感
6. 技能为什么这样设计
7. 玩法定位
8. 相关卡牌关系
9. 设计备注
```

---

## 二、路由结构

单卡详情路由：

```text
/cards/:id
```

分类入口：

```text
/cards/monster/:id
/cards/treasure/:id
/cards/territory/:id
```

第一阶段可只实现：

```text
/cards/:id
```

分类路由后续再扩展。

CardCodexPage

## 四、CardCodexHero

用途：让玩家确认正在查看哪张卡。

结构：

```text
卡牌名称
卡牌类型
星级 / 阵营 / 妖域 / 分类
一句话定位
返回图鉴按钮
```

数据来源：

```text
规则/V1.2-基础卡表.md
对应单卡志文档
```

禁止在页面中手写第二份基础卡牌信息。

---

## 五、CardIdentityPanel

用途：展示基础卡牌身份。

结构：

```text
名称
星级
类型
阵营 / 妖域 / 分类
是否有技能
基础版状态
适用模式
```

说明：

```text
这些字段必须来自基础卡表或生成后的结构化数据。
```

---

## 六、CardImagePanel

用途：展示卡牌实物或卡面图。

结构：

```text
卡牌正面预览
放大查看按钮
印刷资源状态
占位图状态
```

资源优先级：

```text
1. web/public/assets/print/v1/manifest.json 中登记的真实印刷资源
2. 项目内已确认的卡面图
3. 占位框
```

禁止使用随机外部图片。

禁止用 AI 临时生成图替代已确认卡面。

---

## 七、CardSourceSection

用途：展示原著背景来源。

适用于：

```text
妖怪卡
法宝卡
地盘卡
```

结构：

```text
原著出处
原著身份
原著相关情节
与本游戏版本的取舍
不采用的设定说明
```

边界：

```text
只展示与卡牌设计有关的背景。
不写完整人物志。
不复制大段原著文本。
不把世界观外传内容混入基础卡说明。
```

---

## 八、CharacterImageDesignSection

用途：展示形象设计方向。

妖怪卡结构：

```text
体型轮廓
面部特征
服饰 / 甲胄 / 饰品
武器 / 法器
动作姿态
色彩气质
阵营识别点
禁止元素
```

法宝卡结构：

```text
主体造型
材质
符文 / 光效
比例
使用状态
禁止元素
```

地盘卡结构：

```text
场景类型
地貌元素
建筑元素
妖域识别点
气氛关键词
禁止元素
```

说明：

```text
这一部分展示美术设计依据，不改变卡牌规则。
```

---

## 九、SkillDesignSection

用途：展示技能设计灵感与原因。

仅适用于有技能的卡牌。

结构：

```text
当前技能文案
技能效果类型
设计灵感来源
为什么对应这个角色 / 法宝
为什么这样简化
为什么适合当前星级
与其他卡牌的互动
平衡注意点
```

边界：

```text
技能文案以规则/V1.2-基础卡表.md 为准。
本页只能解释，不能改写技能。
不得新增隐藏效果。
不得新增规则关键词。
不得新增数值体系。
```

无技能卡处理：

```text
显示“当前基础版无技能”。
可展示为什么基础版不加技能。
不临时补技能。
```

---

## 十、GameplayRoleSection

用途：解释这张卡在游戏里的定位。

结构：

```text
基础定位
适合使用时机
抢地盘中的作用
防守中的作用
与法宝 / 地盘 / 阵营的关系
新手理解提示
```

边界：

```text
只做玩法理解说明。
不新增攻略数值。
不承诺最优解。
不把测试结论写成正式规则。
```

---

## 十一、RelatedCardsSection

用途：展示相关卡牌关系。

结构：

```text
同阵营卡牌
同原著关联卡牌
技能互动卡牌
同妖域地盘
相关法宝
```

数据来源：

```text
规则/V1.2-基础卡表.md
单卡志文档中的关联说明
```

禁止手写维护第二份关系表。

---

## 十二、DesignNotesSection

用途：展示设计备注。

结构：

```text
设计目标
被舍弃方案
版本变更记录
美术审核备注
规则审核备注
后续扩展可能性
```

边界：

```text
后续扩展只作为备注，不进入基础版规则。
4星、5星、收藏版等扩展内容不得混入基础牌库说明。
```

---

## 十三、BackToCardsSection

用途：引导返回图鉴或继续浏览。

结构：

```text
返回卡牌图鉴
上一张
下一张
同阵营更多
同类型更多
```

---

## 十四、列表页与卡志页关系

卡牌图鉴列表页只展示轻量信息：

```text
卡图
名称
星级
类型
阵营 / 分类
是否有技能
```

单卡卡志页展示深度内容：

```text
原著背景
形象设计
技能灵感
玩法定位
相关卡牌
设计备注
```

列表页不展开长文。

长文统一进入单卡卡志页。

---

## 十五、移动端结构

移动端单卡卡志页：

```text
卡图
基础信息
折叠分区
底部返回按钮
```

分区顺序：

```text
基础信息
原著背景
形象设计
技能设计
玩法定位
相关卡牌
设计备注
```

移动端长内容必须可折叠。

---

## 十六、桌面端结构

桌面端单卡卡志页：

```text
左侧：卡牌图 / 基础信息 / 返回图鉴
右侧：卡志正文
顶部：卡名与定位
底部：相关卡牌
```

桌面端可以加页内目录：

```text
基础
原著
形象
技能
玩法
关联
备注
```

---

## 十七、数据边界

允许读取：

```text
规则/V1.2-基础卡表.md
妖怪志/卡名/卡名.md
法宝志/法宝名/法宝名.md
web/public/assets/print/v1/manifest.json
```

不作为单卡卡志来源：

```text
规则/游戏手册.md
规则/指南卡.md
卡牌成品/印刷说明.md
```

原因：

```text
游戏手册和指南卡是玩家展示派生文件。
印刷说明是生产交付文件。
单卡卡志应读取基础卡表与对应单卡志。
```

---

## 十八、当前结论

单卡卡志应作为 `/cards/:id` 的深度详情页存在。

卡牌图鉴负责浏览。

单卡卡志负责解释：

```text
这张卡是谁
来自哪里
为什么长这样
为什么技能这样设计
在游戏里做什么
和哪些卡有关
后续是否有扩展空间
```

第一阶段可以先做页面结构和占位区，不填充具体单卡内容。
