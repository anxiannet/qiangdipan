# 《夕妖：抢地盘》网站目录位置约定

## 文件定位

本文件用于确定《夕妖：抢地盘》网站相关文件在仓库中的放置位置。

本文件只约定目录位置，不写代码，不修改规则，不新增卡牌。

---

## 一、结论

网站相关内容分成两类目录：

```text
网站/
web/
```

其中：

```text
网站/ = 中文规划文档目录
web/ = 正式网站工程目录
```

当前正式网站访问地址：

```text
https://qdp.weijie.sg
```

---

## 二、为什么不把正式网站工程放在“网站/”目录

`网站/` 用于保存中文规划文档。

例如：

```text
网站/完整网站架构规划.md
网站/游戏界面设计方向.md
网站/联网对战技术方案.md
网站/开发路线图.md
网站/网站技术栈方案.md
网站/网站目录位置约定.md
网站/网站部署状态.md
```

正式工程不建议放在中文路径中，原因：

```text
1. Next.js / Vercel / GitHub Actions / 脚本工具对英文路径更稳定。
2. npm、Node、构建缓存、部署命令更适合英文工程目录。
3. 后续多人协作、CI、部署文档更清晰。
4. 避免中文目录在不同系统、终端、编码环境下出现路径问题。
```

因此正式网站工程统一放在英文目录：

```text
web/
```

## 三、目录职责

### 1. `网站/`

用途：

```text
产品规划
技术规划
界面规划
联网方案
开发路线图
目录约定
部署状态记录
```

特点：

```text
中文文档
给项目管理和设计决策使用
不参与前端构建
不作为可部署网站工程
```

---

### 2. `web/`

用途：

```text
正式网站工程
Next.js 项目
React 页面
PixiJS 8 游戏客户端
TypeScript game-core
部署配置
```

特点：

```text
英文路径
参与 npm install / build / deploy
当前正式部署入口对应该工程
```

## 五、旧静态原型的位置处理

旧静态原型已从根目录移除：

```text
index.html
pve.html
ai.html
static/
data/
电子原型/
```

这些文件属于历史验证阶段文件，不再作为当前网站入口。

后续规则：

```text
1. 不继续扩展根目录 HTML 原型。
2. 新的正式网站代码进入 web/。
3. 当前对外网站入口使用 https://qdp.weijie.sg。
4. 规则验证经验沉淀到规则文档和网站规划文档，不通过旧 HTML 原型继续维护。
```

## 六、部署约定

### 1. 当前部署

当前正式网站已部署：

```text
https://qdp.weijie.sg
```

工程目录：

```text
web/
```

用途：

```text
正式网站入口
官网工程骨架验证
后续卡牌图鉴、规则中心、众筹预热、PixiJS 游戏客户端迭代入口
```

### 2. 后续部署原则

正式网站继续部署 `web/`：

```text
web/ -> qdp.weijie.sg
```

后续若需要预览环境，可再配置：

```text
preview / staging
```

---

## 七、数据文件位置

正式网站运行时数据位置：

```text
web/public/data/
```

原则：

```text
web/public/data/ 是网站运行时读取数据。
数据来源仍以规则文件为准。
不得在网站中维护第二套规则。
```

后续可通过脚本从规则文件生成数据，再写入 `web/public/data/`。
