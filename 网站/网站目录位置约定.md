# 《夕妖：抢地盘》网站目录位置约定

## 文件定位

本文件用于确定《夕妖：抢地盘》网站相关文件在仓库中的放置位置。

本文件只约定目录位置，不写代码，不修改规则，不新增卡牌。

---

## 一、结论

网站相关内容分成两类目录：

```text
网站/
web/
```

其中：

```text
网站/ = 中文规划文档目录
web/ = 正式网站工程目录
```

---

## 二、为什么不把正式网站工程放在“网站/”目录

`网站/` 已经用于保存中文规划文档。

例如：

```text
网站/完整网站架构规划.md
网站/游戏界面设计方向.md
网站/联网对战技术方案.md
网站/开发路线图.md
网站/网站技术栈方案.md
```

正式工程不建议放在中文路径中，原因：

```text
1. Next.js / Vercel / GitHub Actions / 脚本工具对英文路径更稳定。
2. npm、Node、构建缓存、部署命令更适合英文工程目录。
3. 后续多人协作、CI、部署文档更清晰。
4. 避免中文目录在不同系统、终端、编码环境下出现路径问题。
```

因此正式网站工程统一放在英文目录：

```text
web/
```

```text

```

特点：

```text

后续连接 Vercel 或其他部署平台
```

## 五、当前静态原型的位置处理

当前已有静态原型仍暂时保留在仓库根目录和现有目录中：

```text
index.html
pve.html
ai.html
static/
data/
电子原型/
```

这些属于历史验证阶段文件。

后续迁移规则：

```text
1. 不继续扩展根目录 HTML 原型。
2. 新的正式网站代码进入 web/。
3. 当前静态页面只作为旧原型或 GitHub Pages 临时入口保留。
4. 当 web/ 正式可部署后，再决定是否删除或归档旧原型。
```

## 六、部署约定

### 1. 当前阶段

当前 GitHub Pages 可继续使用根目录静态页面：

```text
index.html
pve.html
```

用途：

```text
临时试玩
规则验证
外部快速访问
```

### 2. 正式阶段

正式网站建议部署 `web/`：

```text
web/ -> Vercel
```

或：

```text
web/ -> GitHub Actions build -> GitHub Pages / 静态托管
```

优先建议：

```text
Vercel 部署 web/
```

原因：

```text
Next.js 支持更完整
后续接 Supabase 更方便
预览环境和分支部署更方便
```

## 七、数据文件位置

当前已存在：

```text
data/cards.v1.json
data/duel.v01.json
```

短期继续放在根目录 `data/`，供旧原型读取。

进入 `web/` 正式工程后，应复制或构建到：

```text
web/public/data/
```

原则：

```text
根目录 data/ 仍可作为项目级导出数据。
web/public/data/ 是网站运行时读取数据。
二者需要保持同步，不能出现两套含义不同的数据。
```

后续可通过脚本从规则文件生成 data，再复制到 web/public/data。
