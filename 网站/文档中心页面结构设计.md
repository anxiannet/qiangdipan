# 《夕妖：抢地盘》分散具体页面结构设计

## 文件定位

本文件用于废止此前“资料馆 / 文档中心”式集中入口方案，改为分散到具体业务页面的结构方案。

说明：本文件仍位于 `网站/` 目录中，作为内部规划记录；但前台不建立 `/docs`、不建立 `/library`，也不建立前端 Markdown 内容文件夹。

用户看到的是具体页面：

```text
卡牌
规则
技能评级
美术档案
印刷成果
众筹预热
开发记录
```

用户不需要知道这些页面背后来自哪些仓库文件。

---

## 一、废止方案

废止以下前台概念：

```text
文档中心
资料馆
文档详情
文档列表
/docs
/library
前端 Markdown 内容文件夹
```

不再把资料集中堆到单独入口。

---

## 二、当前方案

所有资料分散进入对应业务页面：

```text
卡牌资料 -> /cards
规则资料 -> /rules
技能评级 -> /rules/skills 与 /rules/skill-rating
美术资料 -> /art
插画历史 -> /art/illustration-history
印刷生产 -> /print
众筹运营 -> /crowdfunding
网站开发 -> /devlog/website
```

页面之间通过“相关页面 / 历史记录 / 继续阅读”连接。

---

## 三、页面结构通用规则

每个具体页面都应具备：

```text

面包屑
页面标题
主体内容
相关页面
历史记录入口
继续阅读
底部导航
```

长页面可增加：

```text
左侧同类导航
右侧页内目录
上一篇 / 下一篇
```

## 十一、内容来源边界

前端页面不新建 Markdown 内容文件。

页面内容来源于仓库中已有对应资料文件，或后续由构建脚本从源文件生成结构化数据。

禁止：

```text
在 web/ 下新建 content/docs/。
在 web/ 下新建 markdown 文档库。
把规则、卡表、技能复制成第二份前端内容。
```

允许：

```text
读取仓库源文件。
生成只读 JSON。
在页面组件中渲染结构化数据。
保留仓库原始文件作为唯一来源。
```

---

## 十二、当前结论

网站采用分散具体页面体系。

没有文档中心。

没有资料馆。

没有前端 Markdown 内容文件夹。

所有内容进入对应模块页面，并通过相关页面和继续阅读形成浏览路径。
