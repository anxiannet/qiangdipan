## 二、总技术方向

采用双层架构：

```text
官网层：Next.js / React 负责展示、图鉴、规则、众筹、开发日志
游戏层：PixiJS 8 负责全屏游戏桌面、卡牌表现、动画和交互
```

原则：

```text
官网像产品官网。
游戏像卡牌游戏客户端。
规则引擎独立于 UI。
PixiJS 8 只负责渲染与交互表现，不直接承担规则判定。
```

---

## 三、核心技术栈

| 模块 | 技术选型 | 用途 |
|---|---|---|
| 官网框架 | Next.js | 首页、规则、图鉴、众筹、开发日志、SEO |
| UI框架 | React | 页面组件与游戏外壳 |
| 语言 | TypeScript | 卡牌数据、规则状态、接口类型 |
| 游戏渲染 | PixiJS 8 | 全屏游戏桌面、卡牌对象、动画、特效 |
| 状态管理 | Zustand | 本地状态、房间状态、UI状态 |
| 动画编排 | GSAP | 卡牌移动、翻面、缩放、时间线动画 |
| 音效 | Howler.js | 按钮、抽牌、出牌、结算反馈 |
| 样式 | Tailwind CSS / CSS Modules | 官网与游戏外壳样式 |
| 数据 | 静态 JSON → 后续数据库 | 卡牌、规则、图鉴、模式配置 |
| 后端 | Supabase → 后续独立服务 | 登录、房间、记录、反馈、众筹意向 |

## 四、PixiJS 8 的项目定位

PixiJS 8 负责：

```text
游戏画布
游戏大厅视觉
卡牌 Sprite
场景 Container
桌面图层
动画对象
粒子与光效
鼠标 / 触摸交互
资源加载后的纹理展示
```

PixiJS 8 不负责：

```text
规则来源
胜负判定
卡牌数据库维护
联网权威状态
众筹表单
官网 SEO
Markdown 规则展示
```

---

## 五、React 与 PixiJS 的边界

React 负责：

```text
页面路由
官网布局
规则阅读
图鉴筛选
众筹表单
登录状态
进入游戏前后的外壳
```

PixiJS 负责：

```text
游戏画布内的桌面表现
卡牌对象
游戏动画
游戏内按钮
场景反馈
```

边界原则：

```text
不要用 React 渲染正式游戏桌面上的每一张卡牌。
不要用普通 HTML 模拟正式游戏桌面。
React 可以包住 PixiJS Canvas，但不接管 PixiJS 内部对象。
```

## 六、规则引擎独立原则

规则引擎采用 TypeScript 独立模块。

建议目录：

```text
game-core/
  cards/
  rules/
  effects/
  actions/
  state/
  validators/
  reducers/
  ai/
```

职责：

```text
校验玩家操作
执行卡牌效果
处理回合流程
处理结算
生成事件序列
输出新的游戏状态
```

原则：

```text
game-core 不依赖 PixiJS。
game-core 不依赖 React。
game-core 可以被人机、AI验证、联网服务器和回放系统复用。
```

## 九、联网方案

当前阶段：

```text
Next.js 正式网站工程已建立并部署
暂不启用复杂联网
先完成官网、图鉴、规则中心、众筹预热和 PixiJS 游戏层基础结构
```

后续阶段：

```text
Supabase Auth
Supabase Postgres
Supabase Realtime
Supabase Storage
Edge Functions 或 Node.js 游戏服务
```

远期阶段：

```text
独立 WebSocket 游戏服务器
Redis 房间状态
Postgres 持久化
对象存储保存回放
```

联网原则：

```text
服务器权威。
客户端只提交操作。
服务器验证并结算。
客户端根据事件播放动画。
```
