# 《夕妖：抢地盘》完整网站架构规划

## 文件定位

本文件用于规划《夕妖：抢地盘》的官网、卡牌资料库、规则展示、众筹预热、电子试玩与联网游戏架构。

本文件不新增基础规则，不修改卡牌数据，不维护第二份卡表。

规则与卡牌唯一来源仍为：

```text
当前项目记忆.md
规则/当前规则.md
规则/V1.2-基础卡表.md
规则/未来扩展与双人对战计划.md
规则/游戏手册.md
```

网站只能读取、展示、验证和表现现有规则，不能创建平行规则体系。

---

## 一、产品定位

网站不是单纯展示官网，而是《夕妖：抢地盘》的数字化入口。

网站承担四类目标：

```text
1. 展示实体卡牌产品
2. 展示卡牌信息与规则
3. 承接众筹预热与预售意向
4. 支持线上试玩、人机验证、多人联网游戏
```

当前阶段定位：

```text
试玩验证 + 产品预热 + 众筹意向收集
```

暂不直接定位为正式发售平台。

---

## 二、总体结构

网站分为两个层级：

```text
官网层：展示、规则、卡牌、众筹、账号、社区
游戏层：全屏游戏大厅 + 人机 + 联网对战 + 4人抢地盘
```

原则：

```text
官网可以像网站。
游戏页面不能像网页，必须像一个卡牌游戏客户端。
```

## 六、游戏界面方向

### 1. 总原则

游戏页面不能出现明显网页感。

避免：

```text
普通网页导航栏
网页表格
长页面滚动
传统按钮堆叠
普通 HTML 卡片
后台管理系统感
```

采用：

```text
全屏游戏 UI
固定游戏桌面
卡牌飞行动画
战斗特效
游戏按钮
厚重卡牌
场景背景
```

视觉关键词：

```text
炉石式布局
西游妖怪洞府
厚重卡牌
金边 UI
木质 / 石质 / 铜纹按钮
战斗特效
卡牌飞行动画
```

说明：参考炉石式交互和桌面布局，但不能复制其具体 UI 或美术资产。

---

### 2. 游戏大厅

大厅像客户端，而不是网页首页。

布局：

```text
背景：妖怪洞府 / 云雾山门 / 妖王大厅
中间：主模式入口
左侧：玩家头像、等级、收藏
右侧：活动、众筹、公告
底部：卡牌、规则、商店、对战、设置
```

模式按钮：

```text
抢地盘 4人局
妖王对战 1v1
人机练习
规则教学
卡牌图鉴
```

---

### 3. 双人对战桌面

布局：

```text
上方：对手区域
中间：战场 / 地盘
下方：玩家区域
左侧：地盘生命 / 妖气
右侧：回合按钮
底部：手牌扇形展开
```

动画：

```text
抽牌：牌库飞入手牌
打出：手牌飞到场上
攻击：卡牌向目标冲撞
消灭：碎裂 / 烟雾
吹回：卡牌飞回手牌
回合结束：大按钮高亮切换
```

---

### 4. 4人抢地盘桌面

4人局不能套用 1v1 战场。

建议布局：

```text
中间：当前地盘牌
四角：四名玩家妖怪区
顶部：公共牌库 / 弃牌区
底部：当前玩家手牌
右侧：当前回合流程
```

抢地盘表现：

```text
地盘牌放大
各玩家派妖怪进场
妖怪围绕地盘站位
结算时显示谁抢下地盘
```

目标：保留实体桌游的桌面感、聚会感和抢地盘互动感。

## 七、核心系统模块

### A. 内容展示模块

负责：

```text
首页
卡牌图鉴
规则中心
众筹页
开发日志
FAQ
```

适合静态化，方便展示和搜索收录。

---

### B. 卡牌数据库模块

负责：

```text
卡牌基础数据
卡图资源
技能文本
规则解释
模式适配
卡牌版本
```

数据来源：

```text
规则/V1.2-基础卡表.md
规则/未来扩展与双人对战计划.md
其他单卡文档
```

目标数据文件：

```text
data/cards.v1.json
data/duel.v01.json
data/rules.v01.json
```

这些 JSON 应由规则文件整理生成，不作为新的规则来源。

---

### C. 游戏规则引擎

规则不能写死在 UI 中。

建议单独抽离：

```text
game-core/
  cards
  rules
  effects
  turn-flow
  combat
  validation
  ai
```

复用目标：

```text
人机对战
联网对战
AI自动验证
回放系统
未来手机 App
```

---

### D. 人机 AI 模块

分三层：

```text
初级 AI：能出牌、能攻击
测试 AI：批量跑局，统计胜率
策略 AI：评估场面、保留资源、优先斩杀
```

当前优先实现：

```text
初级 AI
测试 AI
```

---

### E. 联网房间模块

需要支持：

```text
创建房间
加入房间
房间码
准备状态
座位
断线重连
观战
聊天 / 表情
```

---

### F. 对战同步模块

必须采用服务器权威模式。

流程：

```text
玩家点击操作
↓
客户端发送 action
↓
服务器验证是否合法
↓
服务器更新 game state
↓
广播给所有玩家
↓
客户端播放动画
```

不能让各客户端自行决定结算结果。

---

### G. 众筹 / 预售模块

早期只做意向登记：

```text
邮箱 / 微信
想买几盒
所在地区
是否愿意试玩
反馈留言
```

后期再接支付或众筹平台。

可选渠道：

```text
Stripe
PayNow
Shopify
Gumroad
Kickstarter / 摩点 / 小程序
```

---

### H. 后台管理模块

需要简单后台：

```text
卡牌数据检查
规则版本管理
玩家反馈
众筹意向列表
试玩数据统计
BUG记录
```

### 2. 双人对战

基于当前：



### 3. 4人抢地盘

这是主产品模式。

数字版目标：

```text
教学
试玩
推广
众筹转化
远程体验
```

实现顺序：

```text
本地热座
好友房联网

```

重点设计：

```text
座位系统
当前玩家高亮
```

```text

```

## 十一、当前版本不做事项

当前阶段暂不做：

```text
正式付费系统
复杂匹配系统
排行榜结算
完整商城
新卡包售卖
独立对战版全新卡池
复杂社交系统
```

这些功能在规则、实体测试、众筹预热稳定后再进入后续版本。

## 十二、当前执行结论

当前建议执行范围：

```text
先做：官网 + 炉石式人机对战 + 卡牌图鉴 + 规则中心 + 众筹预热
暂不直接做完整多人联网
但架构上预留联网
```

优先级：

```text
1. 统一现有原型入口
2. 抽离卡牌数据
3. 重做人机对战为全屏游戏桌面
4. 建立卡牌图鉴
5. 建立规则中心
6. 建立众筹预热页
7. 做4人抢地盘本地版
8. 做好友房联网
```
