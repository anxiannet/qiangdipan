# 《夕妖：抢地盘》网站开发路线图

## 文件定位

本文件记录《夕妖：抢地盘》完整网站与数字试玩系统的开发顺序。

本路线图服务于：

```text
官网展示
卡牌图鉴
规则中心
众筹预热
人机对战
4人抢地盘
多人联网
```

本文件不修改规则，不新增卡牌，不替代现有规则文件。

---

## 一、开发总原则

```text
先官网入口
再数据抽离
再炉石式人机
再4人抢地盘本地版
最后联网
```

原因：

```text
1. 当前规则仍在测试，不能过早重投入复杂联网。
2. 卡牌和规则数据必须先统一来源。
3. 游戏界面需要先建立客户端感。
4. 4人主玩法需要先本地跑通，再联网。
5. 众筹预热需要展示页、规则页和试玩页同步支撑。
```

---

```text
网站/游戏界面设计方向.md
网站/联网对战技术方案.md
网站/开发路线图.md
```

完成标准：

```text
网站目标清楚
游戏界面方向清楚
联网技术路线清楚
开发阶段清楚
```

## 三、阶段 1：统一入口与信息架构

目标：把现有原型整理成一个统一网站入口。

页面：

```text
首页
游戏大厅
人机对战入口
AI验证入口
规则入口
卡牌图鉴入口
众筹预热入口
```

保留：

```text
现有人机原型
AI验证页面
已有 GitHub Pages 入口
```

调整：

```text
不再让用户直接面对散落的 html 文件
所有试玩入口从游戏大厅进入
```

完成标准：

```text
用户打开首页后，可以清楚进入：看规则、看卡牌、试玩、众筹预热。
```

---

## 四、阶段 2：抽离卡牌与规则数据

目标：前端不再手写卡牌数据。

建立数据文件：

```text
data/cards.v1.json
data/duel.v01.json
data/rules.v01.json
```

数据来源：

```text
规则/V1.2-基础卡表.md
规则/未来扩展与双人对战计划.md
规则/双人对战V0.1-召唤延迟调整.md
规则/游戏手册.md
```

要求：

```text
JSON 只是展示和程序读取数据，不成为新的规则来源。
每次更新必须回溯到规则文件。
```

完成标准：

```text
卡牌图鉴、人机对战、AI验证共用同一份 JSON 数据。
```

---

## 五、阶段 3：炉石式人机对战重做

目标：把当前人机页面升级为全屏游戏客户端感。

重点：

```text
固定游戏桌面
无整页滚动
手牌扇形
卡牌悬停放大
结束回合大按钮
可打出卡牌高亮
召唤延迟状态标记
攻击动画
消灭 / 吹回反馈
```

不做：

```text
复杂联网
完整账号系统
商城
排行榜
```

完成标准：

```text
玩家感觉是在玩一个卡牌游戏，而不是测试网页。
人机对战可以完整跑完一局。
```


## 九、阶段 7：本地规则引擎重构

目标：为联网做准备。

将游戏操作统一为 action：

```text
play_card
select_target
attack
claim_territory
end_turn
choose_option
```

将结算统一为 event：

```text
card_drawn
card_played
monster_attacked
monster_destroyed
monster_bounced
territory_claimed
life_changed
turn_started
turn_ended
```

完成标准：

```text
人机、双人、本地4人都使用同一套规则引擎。
```

---

## 十、阶段 8：好友房联网

目标：实现最小可用联网对战。

先做：

```text

准备
开始

结束结算
```

先支持：

```text

```

```text

```

完成标准：

```text
两个玩家可远程完成一局双人对战。
```
