# 《夕妖：抢地盘》联网对战技术方案

## 文件定位

本文件规划《夕妖：抢地盘》数字版的联网对战技术方案。

本文件不定义新规则，只定义如何让现有规则在线上稳定运行。

关联文件：

```text
网站/完整网站架构规划.md
网站/游戏界面设计方向.md
规则/未来扩展与双人对战计划.md
规则/游戏手册.md
```

---

## 一、核心原则

联网对战必须采用服务器权威模式。

原则：

```text
客户端只负责展示和提交操作。
服务器负责验证、结算和广播结果。
```

禁止：

```text
各客户端自行结算游戏结果
客户端直接修改最终 game state
前端绕过规则校验
用聊天房间逻辑代替对战同步逻辑
```

---

## 二、基础流程

标准操作流程：

```text
玩家点击操作
↓
客户端生成 action
↓
发送到服务器
↓
服务器检查是否合法
↓
服务器调用规则引擎结算
↓
生成新的 game state
↓
广播给所有玩家
↓
客户端播放动画并更新界面
```

---

## 三、核心对象

### 1. Room 房间

房间字段：

```text
room_id
mode
status
owner_user_id
max_players
created_at
updated_at
```

mode 可选：

```text
pve
local_duel
duel_online
land_4p_online
spectator
```

status 可选：

```text
waiting
ready
playing
finished
abandoned
```

---

### 2. Player 玩家

字段：

```text
user_id
room_id
seat_index
nickname
avatar
is_ready
is_connected
last_seen_at
```

座位：

```text
双人对战：0 / 1
4人抢地盘：0 / 1 / 2 / 3
```

---

### 3. GameState 游戏状态

GameState 是服务器权威状态。

包含：

```text
room_id
mode
version
turn_player
phase
players
zones
public_state
hidden_state
log
winner
```

公开状态：

```text
生命
妖气
场上妖怪
已占地盘
弃牌堆数量
牌组剩余数量
当前阶段
```

隐藏状态：

```text
玩家手牌
牌组顺序
部分技能查看信息
```

隐藏状态只能发给对应玩家，不能广播给所有人。

---

### 4. Action 玩家操作

Action 是玩家提交的唯一输入。

示例：

```text
play_card
select_target
attack
end_turn
choose_option
ready
concede
send_emote
```

每个 action 必须包含：

```text
action_id
room_id
user_id
seat_index
type
payload
client_time
```

服务器补充：

```text
server_time
sequence_number
validation_result
```

## 四、规则引擎要求

规则引擎必须独立于 UI。

建议结构：

```text
game-core/
  cards/
  rules/
  effects/
  actions/
  state/
  validators/
  reducers/
  ai/
```

规则引擎输入：

```text
current_state
action
```

规则引擎输出：

```text
next_state
events
errors
```

events 用于前端播放动画：

```text
card_drawn
card_played
monster_attacked
monster_destroyed
monster_bounced
life_changed
turn_started
turn_ended
territory_claimed
```

## 五、双人对战联网方案

双人对战使用《妖王对战 V0.1》规则。

阶段：

```text
waiting
mulligan_optional_later
turn_draw
turn_energy
main
attack
end
finished
```

当前 V0.1 暂无起手换牌，可以先不做 mulligan。

客户端操作：

```text
打出妖怪
选择目标
普通攻击
结束回合
认输
表情
```

服务器校验：

```text
是否轮到该玩家
是否处于合法阶段
是否有足够妖气
卡牌是否在该玩家手牌
目标是否合法
召唤延迟是否允许普通攻击
是否已经攻击过
生命是否归零
```

---

## 六、4人抢地盘联网方案

4人模式是主玩法，需要独立状态机。

基本阶段：

```text
setup
reveal_territory
player_action
commit_monsters
resolve_territory
cleanup
next_round
finished
```

4人局重点：

```text
座位顺序
当前玩家提示
地盘争夺归属
多玩家目标选择
临时公开信息
结算动画同步
断线重连
```

服务器需要广播：

```text
当前地盘
当前阶段
当前玩家
各玩家公开区域
结算结果
```

不能广播：

```text
其他玩家手牌内容
其他玩家牌组顺序
隐藏选择内容
```

---

## 七、断线重连

断线重连要求：

```text
玩家重连后按 seat_index 回到原座位
服务器发送当前完整可见状态
隐藏信息只发给该玩家
未完成 action 不自动重复执行
```

房间超时策略：

```text
短线：保留座位
长期离线：允许托管 AI / 判负 / 房主处理
```

具体时长后续按测试确定。

---

## 八、观战与回放

### 1. 观战

观战者只能接收公开状态。

观战禁止：

```text
查看玩家手牌
查看牌组顺序
提交游戏 action
```

### 2. 回放

回放不保存每一帧画面，只保存：

```text
初始随机种子
初始牌组
action 序列
event 序列
最终结果
```

回放时由规则引擎重放。


---

## 十一、防作弊要求

必须做到：

```text
客户端不能决定抽到哪张牌
客户端不能决定战斗结果
客户端不能修改生命和妖气
客户端不能查看隐藏信息
每个 action 都有服务器校验
```

随机数：

```text
由服务器生成随机种子。
洗牌在服务器执行。
回放保存种子和 action 序列。
```

## 十二、开发顺序

### 第 1 步：本地规则引擎

```text
抽离人机对战逻辑
所有操作改成 action
所有结算输出 events
```

### 第 2 步：本地热座

```text
双人本地
4人抢地盘本地
```

### 第 3 步：好友房

```text
创建房间
加入房间
准备
开始
同步公开状态
```

### 第 4 步：完整服务器权威

```text
服务器验证 action
服务器结算 state
广播 events
```

### 第 5 步：断线重连与回放

```text
重连
观战
回放
对战记录
```
